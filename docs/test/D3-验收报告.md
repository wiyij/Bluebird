## 6　发现的问题（按优先级）

### P1　改一次颜色出现两条系统提示（界面瑕疵，建议修）

`client/gui.py::BluebirdApp.set_color` 本地追加「你把颜色改成了绿色」，服务端
`USER_COLOR` 广播又渲染一条「alice 的颜色改为 绿色」。截图 `docs/gui/D3-main.png`
里两条紧挨着，T09 演示时一眼能看见。

修法：删掉 `set_color` 里那行 `append_system`（服务端广播已经含自己；万一非法颜色被拒，
本地那条反而会说错）。

### P2　一键启动：从没登录过时服务端永不自退（运维坑，建议修）

`server/server.py::_sweep_loop` 里 `if … or not self._had_client: continue` ——
启动后**一个人都没登录**时不计空房时间。复验时本机 `8888` 上就挂着一个 11:27:16 起、
半个多小时未退的服务端（`logs/server.log` 可查），它会一直被 `start_chat.py` 复用：
改了代码再双击，跑的还是这个旧进程。

README 写的是「关掉所有窗口后，服务端最后一个客户端离开 2 分钟自动退出」，与实现不符。

修法：`exit_when_idle > 0` 时从启动那一刻开始计空房（去掉 `_had_client` 门槛），
手动起服务端不传 `--idle-exit`，不受影响。

### P3　3001 提示可能落进错的私聊窗（低风险）

`client/gui.py::_handle_error` 对 3001 直接取「第一个还活着的私聊窗」，开过两个窗时
可能提示到别人窗里。目前 `PrivateWindow.send` 先做本地在线检查，3001 几乎到不了这里，
属于潜在问题。修法：按错误文案里的昵称匹配，或记录「最近一次私聊目标」。

### P4　在线列表实际宽度 183 逻辑 px，文档写 140（口径不一致）

`client/ui.py:54` 是 140，但 `tk.Listbox` 默认 20 字符宽（约 183 px）把 grid 列撑开了。
两者选一：改文档（140→约 180），或给 Listbox 显式 `width=1` 让 140 生效（代价是长昵称
更容易被截断）。
