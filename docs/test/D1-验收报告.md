### A03　帧编解码　✅ 通过

- `HEADER = struct.Struct(">HBBI")`、`MAGIC=0x4348`、`VERSION=2`、`MAX_BODY=65528`，与文档一致。
- `encode_frame` 用 `json.dumps(..., ensure_ascii=False, separators=(",", ":"))`；`read_frame` 是 `readexactly(8)` → 验 magic → 验 ver → **先验 length 再读体** → `readexactly(length)` → 验 JSON 对象。
- 实测（`docs/test/D1-live.txt`）：
  - 首部 `43 48 02 01 00 00 00 37`，整帧 63 B = 8 + 55，length 与实际正文严格相等；
  - 一条帧拆成「先 4 字节 → sleep 0.2 s → 余下」，服务端仍还原成 `LOGIN_RESP{code:0}`；
  - 谎报 `length=65535` 时不读体、直接断，没有按谎报长度分配内存。

小偏离：清单里的签名是 `read_frame(reader, max_len=65536)`，实现是 `read_frame(reader, max_body=MAX_BODY)`——参数从「整帧上限」改成「正文上限」，由服务端传 `max_frame - 8`。语义等价且更不易错，可以接受。

⚠ 清单里「`{"text":"你好"}` 编码为 8 字节头 ＋ 12 字节体」是**算式笔误**：实测正文 17 字节（`{`1 ＋ `"text"`6 ＋ `:`1 ＋ `"`1 ＋ 你好 6 ＋ `"`1 ＋ `}`1）。代码是对的（length ＝ 实际 UTF-8 字节数），错的是文档口径，`docs/三阶段实施路线.md` 的 S06 也抄了同一个 12。写报告时请改成「以 length 字段为准」。
