## 2　为什么第一步是「拆网络层」而不是直接画界面

界面要的东西和命令行要的东西是同一批：登录结果、名单变化、消息、错误、断线。
如果 GUI 直接把 `cli.py` 里的 `ChatClient` 复制一份，就会出现两套心跳、两套重连、
两套错误文案——D2 复审里那种「改一处忘一处」的 bug 会成倍增长。

所以先立一条线：

```
        ┌──────────────┐        on_event((kind, payload))        ┌──────────────┐
        │ client/net.py│ ───────────────────────────────────────► │  console CLI │
        │ 独立线程 +    │                                         └──────────────┘
        │ asyncio 循环  │        queue.Queue                       ┌──────────────┐
        │              │ ──────► root.after(50) ────────────────► │ tkinter GUI  │
        └──────────────┘                                         └──────────────┘
             ▲
             └── send_group / send_private / set_color / logout（任意线程调，内部 call_soon_threadsafe）
```

**线程边界只有一条规则**：控件只在主线程碰。网络线程的一切都变成事件，
GUI 用 `root.after(50, poll)` 取出来再更新界面。这条规则违反一次，就是「随机崩」。

## 4.1　T13 换网段复验

D3 当天换到了另一个网络（手机热点 `172.20.10.5/28`），正好把 T13 能在一台机器上做的
那一半补掉。判据与证据见 [`D3-net-evidence.txt`](D3-net-evidence.txt)（**11/11**）：

| 判据 | 结果 |
| --- | --- |
| 取到的是局域网地址而不是回环 / 169.254 自动私有地址 | ✅ `172.20.10.5` |
| 客户端用局域网 IP 登录（不是 127.0.0.1） | ✅ code=0 |
| **服务端看到的对端地址是同网段的局域网 IP** | ✅ `peer=('172.20.10.5', …)` |
| 服务端监听在 `0.0.0.0` 而不是只绑回环 | ✅ `[('0.0.0.0', …)]` |
| 三端在线、群聊、私聊隔离、改色广播全部经真实网卡 | ✅ 4 项 |
| 同一个服务端，`127.0.0.1` 也照样能连 | ✅ 两种地址都行 |
| 真实入口 `python -m server.server` 经局域网 IP 可登录 | ✅ |

**这证明了什么**：代码里没有写死 `127.0.0.1`，客户端填什么 IP 就连什么，
换个网段只要改登录窗里的地址，不用动一行代码。

**还差什么**：真正的「另一台机器」。同一台机器连自己的局域网 IP 走的是本机协议栈，
虽然服务端看到的对端地址确实是 WLAN 的 IP（不是回环），但**没有经过交换机/AP**。
现场验收时让同学用手机热点连进来跑一次客户端，这一条才算完整。

> 换网后还确认了一件事：Windows 防火墙对 `python.exe` 已有入站放行规则（Private/Public），
> 换到「公用网络」也不会被静默拦掉。如果没有这条规则，别人连不进来会表现为「连接超时」而
> 不是「被拒绝」——演示前值得先用 `Get-NetFirewallRule` 看一眼。

## 5　三个必须写进报告的决定

1. **字数按字节算，不是按字符。** 协议第 8 章的上限是 2000 **字节**；一个汉字 3 字节、
   emoji 4 字节。所以输入框显示的是 `24/2000 字节`。如果按字符显示，用户打 700 个汉字
   会被 2001 拒掉，而计数器还在说 700/2000 —— 看起来就像 bug。
2. **断线不自动重连，回登录窗。** 《结果示例》决定⑥：零持久化、没有会话令牌，
   断线即丢会话。所以点「重新连接」＝重新走一遍登录，而不是偷偷续上。
   （四天清单里的 A18 指数退避按 v2 裁剪，只用于登录窗里的重试，D4 若还要做再说。）
3. **私聊开独立窗口，群聊与私聊不串。** 演示时把主窗切走，老师看到的就不是
   「一个聊天室 + 若干私聊」了。服务端单投、客户端分窗，两头都要守这条。

## 6　踩到的四个坑（都写进代码注释了）

| 坑 | 现象 | 根因 | 解法 |
| --- | --- | --- | --- |
| **venv 启动器是父进程** | 「杀掉服务端」之后客户端毫无反应，重启脚本又连上了上一轮的服务端 | Windows 上 `.venv\Scripts\python.exe` 会再起一个真解释器；`terminate()` 只杀了启动器 | `tools/procutil.py` 统一 `taskkill /T /F` 杀整棵树 |
| **DPI 不感知** | 150% 屏上字发虚；截图永远歪 1.5 倍 | 进程没声明 DPI 感知，Windows 把窗口当位图拉伸；Tk 给逻辑像素、截图收物理像素 | `prepare_dpi()`：`SetProcessDpiAwareness(1)` + `tk scaling` + 像素常量过 `px()` |
| **`pack(**{"sticky": ...})`** | 登录窗直接抛 `TclError: bad option "-sticky"` | `sticky` 是 `grid` 的选项，`pack` 没有 | 分开写；两种布局别混用参数 |
| **事件泵会被一个坏事件弄死** | 界面「突然不动了」，但其实进程还活着 | `_handle()` 抛异常后 `root.after` 没被重新排上 | `_poll` 里 try/except 兜底 + 打 traceback + 界面提示 |

## 7　没做的（留 D4 或明确不做）

- **T13 的「另一台机器」**：换 IP 这一半已在 §4.1 验完（11/11），还缺第二台设备真走一趟网络。
- **A18 指数退避重连**：v2 无会话续期，按上文决定 2 裁剪；要做只能做成「登录窗重试」。
- **文件传输**：需求里没有，明确不做。
- **历史消息**：零持久化，新进来的人看到的是空聊天区，这是决定⑥的直接后果。

## 8　复现

```powershell
# 1) 起服务端
.\.venv\Scripts\python.exe -m server.server

# 2) 开三个图形客户端（换机器时把 --host 改成服务端 IP）
.\.venv\Scripts\python.exe -m client.gui --name alice
.\.venv\Scripts\python.exe -m client.gui --name bob
.\.venv\Scripts\python.exe -m client.gui --name carol

# 3) 自动化走查（33 项，自己起服务端，约 20 秒）
.\.venv\Scripts\python.exe tools\verify_d3_gui.py

# 3b) 换网复验：走真实网卡而不是回环（11 项）
.\.venv\Scripts\python.exe tools\verify_d3_net.py
.\.venv\Scripts\python.exe tools\verify_d3_gui.py --host 172.20.10.5 --shots

# 4) 带截图（写到 docs/gui/）
.\.venv\Scripts\python.exe tools\verify_d3_gui.py --shots

# 5) 全量测试
.\.venv\Scripts\python.exe -m pytest
```

> 说明：这套走查在本机偶发过「服务端→客户端」一跳 ~3.3 s 的抖动（30 条压测最大 0.001 s，
> 属环境偶发）。因此「列表 1 s 内更新」量的是**事件到手 → 界面渲染**这一段，
> 网络那一跳由压测单独看，两者不混在一起互相甩锅。
