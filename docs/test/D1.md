## 4　怎么读这段字节

以那条 `CHAT_GROUP`（C→S，67 B）为例：

| 字节 | 值 | 含义 |
| --- | --- | --- |
| 0—1 | `43 48` | magic，ASCII `"CH"` |
| 2 | `02` | 协议版本 2 |
| 3 | `10` | 类型 `CHAT_GROUP` |
| 4—7 | `00 00 00 3B` | 正文长度，大端 = 0x3B = **59** |
| 8—66 | … | UTF-8 JSON，59 字节 |

三条可以直接写进报告的结论：

1. **长度按字节算，不按字符算。**「大家好，我是 alice」是 12 个字符，UTF-8 下却是 24 字节：6 个全角字符（大家好我是 + 逗号）各占 3 字节共 18，空格 1 字节，`alice` 5 字节。整条正文 59 字节 = JSON 结构 35 + 文本 24。
2. **发送者收到两份、其他人各一份。** C→S 只有 1 条，S→C 有 2 条——服务端把同一帧扇出给了 2 个在线连接，自己的那份就是界面上的「回显」。扇出时服务端补了 `seq`、`from`、`server_ts`，所以正文从 59 涨到 105。
3. **emoji 占 4 字节。** bob 那条正文 44 字节：`收到` 6 ＋ 空格 1 ＋ 😀 4 ＋ JSON 结构 33。

本机没有管理员权限，装不了 Npcap 抓包驱动，所以**做不到实时抓包**。补的做法分两步：


截图见 [`docs/pcap/D1-frame-wireshark.png`](pcap/D1-frame-wireshark.png)：选中第 1 帧的
`Data (63 bytes)`，下方十六进制窗格高亮 63 字节载荷，开头就是 `43 48 02 01 00 00 00 37`。
图注里写明了「pcap 由真实载荷重放生成」，**答辩时说清楚这一点**：字节是真的，链路层头部是重建的。

有管理员权限的机器上，补一张实时抓包图只要三步：

1. `winget install WiresharkFoundation.Wireshark`（会自动装 Npcap）
2. `tshark -i loopback -f "tcp port 8888" -a duration:30 -w docs\pcap\D1-wireshark.pcapng`
3. 打开 pcapng → 选中带 payload 的包 → **Follow → TCP Stream → Hex Dump** → 截图存
   `docs/pcap/D1-frame-wireshark.png`（覆盖现在这张，正文不用改）
