# D1　双端联调与抓包取证（A07）

> 注：本记录抓于**协议 v1** 时期（帧头版本字节为 `0x01`、正文上限 8192 字节）。
> 协议已升级到 v2（版本字节 `0x02`、正文上限 2000、新增颜色两条消息），抓包方法不变。

> 目的：证明「A 机发出的字节，在线上就是一帧 8 字节头 + JSON」，并留下报告可用的字节级证据。
> 结果：✅ 通过。两个客户端经 tap 代理互通，6 帧全部按协议拆出，中英文与表情正常。

## 1　环境与工具

| 项 | 值 |
| --- | --- |
| 系统 | Windows，Python 3.13.7（`py -3.13`） |
| 抓包工具 | **未安装 Wireshark**（Npcap 服务在，但 `tshark` / `Wireshark.exe` 均不存在） |
| 替代方案 | `tools/tap.py`：应用层 TCP 代理，按协议拆帧后逐帧记录 |
| 服务端 | `py -3.13 -m server.server`，监听 `0.0.0.0:8888`（A08 的路由版） |
| 客户端 | `py -3.13 -m client.cli --port 8889 --name alice`（指向 tap） |

tap 只做字节转发，不改变任何一位；它记录的是**真实链路上的载荷**，只是没有链路层/网络层头部。

## 2　复现步骤

```powershell
# 终端 1：服务端
py -3.13 -m server.server

# 终端 2：抓包代理（8889 → 8888），帧日志写到 docs/pcap/D1-tap.log
py -3.13 -m tools.tap --log docs\pcap\D1-tap.log

# 终端 3、4：两个客户端连 tap
py -3.13 -m client.cli --port 8889 --name alice
py -3.13 -m client.cli --port 8889 --name bob
```

alice 输入「大家好，我是 alice」，bob 输入「收到 😀」，两边终端都能看到两条。

## 4　怎么读这段字节

| 字节 | 值 | 含义 |
| --- | --- | --- |
| 0—1 | `43 48` | magic，ASCII `"CH"` |
| 2 | `01` | 协议版本 1 |
| 3 | `10` | 类型 `CHAT_GROUP` |
| 4—7 | `00 00 00 3B` | 正文长度，大端 = 0x3B = **59** |
| 8—66 | … | UTF-8 JSON，59 字节 |

三条可以直接写进报告的结论：

1. **长度按字节算，不按字符算。** 「大家好，我是 alice」是 12 个字符，UTF-8 下却是 24 字节：6 个全角字符（大家好我是 + 逗号）各占 3 字节共 18，空格 1 字节，`alice` 5 字节。整条正文 59 字节 = JSON 结构 35 + 文本 24。
2. **发送者收到两份、其他人各一份。** C→S 只有 1 条，S→C 有 2 条——服务端把同一帧扇出给了 2 个在线连接，自己的那份就是界面上的「回显」。
3. **emoji 占 4 字节。** bob 那条正文 44 字节：`收到` 6 + 空格 1 + 😀 4 + JSON 结构 33。

## 5　装上 Wireshark 之后怎么补 GUI 截图

三步，与本次抓到的字节一一对应：

1. 抓包：`tshark -i loopback -f "tcp port 8888" -a duration:20 -w docs\pcap\D1-wireshark.pcap`
   （GUI 里就是选中回环网卡 → 过滤器 `tcp.port == 8888` → 开始。）
2. 定位：在任意一条 `TCP payload` 上右键 → **Follow → TCP Stream**。
3. 取证：切到 **Hex Dump**，从 `43 48 01 10` 开始截图；这就是本文件第 3 节的同一批字节。

> 截图存 `docs/pcap/D1-frame-wireshark.png`，替换掉配图即可，其余文字不用改。
