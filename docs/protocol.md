# 局域网聊天室 · 应用层协议 v2

> **状态：已冻结（tag `proto-v2`）**　·　2026-10-23
> 帧格式：8 字节定长首部 + UTF-8 JSON 体　·　15 种消息类型　·　10 个错误码
>
> 本文件是唯一事实源。任何字段、类型码、错误码的改动都必须走同一条链路：
> **改本文档 → 升 `ver`（不兼容时）→ 同步 `shared/protocol.py`、服务端、客户端 → 重新打 tag**。
> 代码与本文档冲突时，以本文档为准；确实要改，先改文档。

## 0　三条纪律

1. **不猜默认值。** 必填字段缺失一律回 `2003` 并丢弃该帧，不做「缺省补齐」。
2. **先验长度，再解析。** `length` 超过上限立刻断开，绝不按谎报的长度分配内存。
3. **报文体永远是 JSON 对象。** 不是数组、不是裸字符串；没有内容就写 `{}`。

## 1　传输层约定

| 项 | 取值 | 说明 |
| --- | --- | --- |
| 传输协议 | TCP | 长连接，一条连接承载全部业务 |
| 服务端端口 | 8888（可用 `--port` 改） | 客户端用系统分配的临时端口 |
| 字符编码 | UTF-8（无 BOM） | **不限制字符集**：中文、英文、emoji、日文原样传输 |
| 时间 | UTC 秒级整数 | 展示时再转本地时区 |
| 单帧上限 | 65536 字节 | 含 8 字节首部 |
| 正文上限 | **2000 字节** | 仅约束 `CHAT_*` 的 `text`，按 UTF-8 字节算 |
| 登录时限 | 10 s | 连接建立后 10 s 内未登录，服务端关闭 |

## 2　帧格式

```
偏移    0     1     2     3     4     5     6     7     8 ──────────►
     ┌───────────┬─────┬─────┬───────────────────────┬────────────────────┐
     │ magic 2B  │ ver │type │   length 4B（大端）    │  body（length 字节）│
     │ 0x43 0x48 │0x02 │0x10 │ 0x00 0x00 0x00 0x2C   │  {"msg_id":…}       │
     └───────────┴─────┴─────┴───────────────────────┴────────────────────┘
```

| 字段 | 长度 | 取值 | 违规时怎么办 |
| --- | --- | --- | --- |
| `magic` | 2 B | 固定 `0x4348`（ASCII `"CH"`） | 不匹配 → **立即关闭，不回包** |
| `ver` | 1 B | 协议版本，当前 `2` | 不匹配 → 回 `ERROR(1003)` 后关闭（v1 客户端连上来就会走到这里） |
| `type` | 1 B | 消息类型码，见第 3 章 | 未知 → 回 `ERROR(2004)`，**连接保持** |
| `length` | 4 B | 报文体字节数，**大端序**；上限 65528 | 超过 → 不回包直接关闭 |
| `body` | `length` B | JSON 对象，UTF-8 | 解析失败 → `ERROR(2003)`，容错一次 |

**为什么用大端**：网络字节序统一大端。Python 里 `struct.Struct(">HBBI")` 的 `>` 就是大端；换成小端，换个平台或与 C 程序对接就会解析错位。

## 3　消息类型总表（15 种）

| 类型码 | 名称 | 方向 | 用途 | 必填字段 |
| --- | --- | --- | --- | --- |
| `0x01` | LOGIN_REQ | C→S | 登录（只认昵称，无口令） | `username` `client_ver` |
| `0x02` | LOGIN_RESP | S→C | 登录结果 | `code` |
| `0x03` | LOGOUT | C→S | 主动退出 | — |
| `0x04` | SET_COLOR | C→S | 改自己的字体颜色 | `color` |
| `0x05` | USER_COLOR | S→C | 某人改色的广播 | `nickname` `color` |
| `0x10` | CHAT_GROUP | C→S→C | 群聊 | `msg_id` `text` |
| `0x11` | CHAT_PRIVATE | C→S→C | 一对一私聊 | `msg_id` `to` `text` |
| `0x12` | CHAT_SYSTEM | S→C | 系统通知 | `text` `level` `ts` |
| `0x20` | USER_LIST | S→C | 全量在线名单（含颜色） | `users` |
| `0x21` | USER_JOIN | S→C | 有人上线 | `nickname` `color` `since` |
| `0x22` | USER_LEAVE | S→C | 有人下线 | `nickname` `reason` |
| `0x30` | PING | C→S | 心跳请求 | — |
| `0x31` | PONG | S→C | 心跳应答 | `server_time` |
| `0x50` | ERROR | S→C | 错误（登录后） | `code` `message` |
| `0x60` | ACK | S→C | 消息回执（可选，本期不用） | `msg_id` `seq` |

> 方向 `C→S→C` 表示「客户端发给服务端，服务端补字段后转发」。

## 4　字段定义

### 4.1 公共字段

| 字段 | 类型 | 谁生成 | 说明 |
| --- | --- | --- | --- |
| `nickname` | string | 服务端（来自登录） | 1—16 字符，`^[A-Za-z0-9_\u4e00-\u9fa5]{1,16}$`；**在线期间唯一** |
| `color` | string | 客户端选，服务端校验 | `black` / `green` / `blue` / `red`，默认 `black` |
| `msg_id` | string | 客户端 | 格式 `昵称-6位序号`，服务端原样透传，用于去重 |
| `seq` | int | 服务端 | 全局单调递增，从 1 开始 |
| `ts` / `server_ts` | int | 双方 | 客户端时间 / 服务端时间（UTC 秒） |
| `code` | int | 服务端 | 错误码，见第 5 章 |
| `reason` | string | 服务端 | `logout` / `disconnect` |

### 4.2 会话（0x01—0x03）

**LOGIN_REQ**

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `username` | string | 是 | 1—16 字符，中英文、数字、下划线 |
| `client_ver` | string | 是 | 客户端版本，如 `"2.0"` |
| `color` | string | 否 | 四色之一；非法值按 `black` 处理，不报错 |

**LOGIN_RESP**

| 字段 | 出现时机 | 说明 |
| --- | --- | --- |
| `code` | 总是 | `0` 成功；非 0 见第 5 章 |
| `message` | 失败时 | 中文原因 |
| `nickname` | 成功时 | 服务端确认的昵称 |
| `color` | 成功时 | 最终生效的颜色 |
| `server_time` | 成功时 | 服务端 UTC 秒 |

> **登录阶段的一切失败都走 `LOGIN_RESP{code≠0}` 然后关闭**，不发 `ERROR`。

**LOGOUT**：空体 `{}`。服务端广播 `USER_LEAVE{reason:"logout"}` 后关闭。

### 4.3 颜色（0x04—0x05）

**SET_COLOR**：`{color}`。服务端校验四色，非法回 `2003`；合法则更新并广播 `USER_COLOR`。

**USER_COLOR**：`{nickname, color}`，广播给所有人（含改色者自己）。**只影响之后的新消息**，已显示的历史消息不回溯变色。

### 4.4 聊天（0x10—0x12）

**CHAT_GROUP**

| 字段 | 类型 | 发送方填 | 服务端补 |
| --- | --- | --- | --- |
| `msg_id` | string | 是 | 透传 |
| `text` | string | 是（≤ 2000 字节） | — |
| `seq` | int | — | 是 |
| `from` | string | — | 是（服务端补，不信任客户端） |
| `server_ts` | int | — | 是 |

服务端把补全后的帧广播给**所有人，含发送者**（发送者那一份就是回显）。

**CHAT_PRIVATE**：同上，另加 `to`（接收者昵称）。

- 目标在线：单投给目标，并回显一份给发送者；
- 目标离线：回 `ERROR(3001)`，**不暂存**（没有离线队列）；
- 自己发给自己：只投递一次。

**CHAT_SYSTEM**：`{text, level, ts, reason?}`。`level` 取 `info` / `warn`。

> **本期实现**：上下线除了 `USER_JOIN` / `USER_LEAVE`（供名单增删）之外，服务端还会广播一条
> `CHAT_SYSTEM` 作为界面提示；客户端不再自己拼「某某进入聊天室」，只负责渲染这一帧。

### 4.5 在线状态（0x20—0x22）

**USER_LIST**：`{users:[{nickname, color, since}], count}`；登录成功后**立即**下发全量。
**USER_JOIN**：`{nickname, color, since}`，广播给除本人外的所有人。
**USER_LEAVE**：`{nickname, reason}`，同上。

### 4.6 心跳（0x30—0x31）

客户端每 15 s 发 `PING`；服务端收到**任何**帧都刷新 `last_active`，收 `PING` 回 `PONG{server_time}`。
服务端每 5 s 扫描，45 s 无帧则判死、广播 `USER_LEAVE{reason:"disconnect"}` 后关闭。

## 5　错误码表（10 个）

| 码 | 含义 | 客户端提示文案 | 连接 |
| --- | --- | --- | --- |
| `1001` | 昵称已被占用 | 该昵称已有人使用，请换一个 | 断开 |
| `1003` | 协议版本不符 | 客户端版本过旧，请更新后再连接 | 断开 |
| `1004` | 昵称格式非法 | 昵称需 1—16 个字符，仅支持中英文、数字与下划线 | 断开 |
| `1006` | 未登录就发了业务帧 | 请先登录 | 断开 |
| `2001` | 消息过长 | 消息超过 2000 字节，请分段发送 | 保持 |
| `2002` | 发送过于频繁 | 发送太快了，请稍后再试 | 保持 |
| `2003` | 报文格式错误 | 客户端数据异常，请重启客户端 | 保持（容错一次） |
| `2004` | 未知消息类型 | 客户端与服务端版本不匹配 | 保持 |
| `3001` | 私聊对象不在线 | 对方不在线 | 保持 |
| `5001` | 服务端内部错误 | 服务器开小差了，请稍后重连 | 保持 |

> 相比 v1 删除了 `1002`（无口令）、`1005`（无会话令牌）、`3002/3003`（无文件）、`4001`（无踢人）。

## 6　连接状态机

```
        TCP 握手完成
              │
              ▼
        ┌───────────┐  非 LOGIN_REQ → ERROR(1006) 并关闭
        │ CONNECTED │  10 s 未登录 → 直接关闭
        └─────┬─────┘
              │ LOGIN_REQ 校验通过
              ▼
        ┌───────────┐  任意帧刷新 last_active；45 s 无帧 → 判死
        │  AUTHED   │
        └─────┬─────┘
              │ LOGOUT / 认证失败 / 超时 / 断开
              ▼
        ┌───────────┐
        │  CLOSING  │ → CLOSED
        └───────────┘
```

## 7　关键时序

### 7.1 登录

```
客户端                                   服务端
  │ ── TCP 三次握手 ────────────────────►│  CONNECTED（10 s 计时）
  │ ── 0x01 LOGIN_REQ ──────────────────►│  校验昵称格式 → 是否重名 → 取颜色
  │    {username, client_ver, color}     │
  │◄─ 0x02 LOGIN_RESP{code:0, nickname,  │  写入在线表
  │      color, server_time}             │
  │◄─ 0x20 USER_LIST{users:[…], count}   │  先给本人全量名单
  │                                      │ ── 0x21 USER_JOIN ──► 其他人
失败分支：
  │◄─ 0x02 LOGIN_RESP{code:1001, message}│  随后关闭
```

### 7.2 群聊

```
A ──0x10 CHAT_GROUP{msg_id, text}──► S
S: 校验长度（≤2000 B）→ 分配 seq → 补 from/server_ts
S ──0x10{msg_id, seq, from, text, server_ts}──► A、B、C（含发送者）
超长 → 只回 A：0x50 ERROR{2001}，不扇出
```

### 7.3 私聊

```
A ──0x11{msg_id, to:"bob", text}──► S
在线：S ──0x11{…, from:"alice", to:"bob", seq}──► B
      S ──0x11{同一份}───────────────────────► A（回显）
离线：S ──0x50 ERROR{3001, "bob 不在线"}─────► A   （不暂存，也不补发）
```

### 7.4 改色

```
A ──0x04 SET_COLOR{color:"green"}──► S
S: 校验四色 → 更新 → 0x05 USER_COLOR{nickname:"alice", color:"green"} ──► 所有人（含 A）
此后 A 的新消息按绿色渲染；历史消息不变色。
```

### 7.5 心跳与断线

```
C ──0x30 PING──► S ──0x31 PONG{server_time}──► C        每 15 s
S: 每 5 s 扫描，now - last_active > 45 → 关闭 + 广播 USER_LEAVE
C: 连接断开 → 回到登录窗，重新走完整登录（v2 不做会话续期）
```

## 8　参数与上限

| 参数 | 取值 | 依据 |
| --- | --- | --- |
| 心跳间隔 / 判死时间 | 15 s / 45 s | 超时 ≥ 3 × 心跳 |
| 心跳扫描周期 | 5 s | 判死误差 ≤ 5 s |

## 附录 A　LOGIN_REQ 逐字节拆解（标准答案）

昵称 `alice`，客户端版本 `1.0`，颜色 `black`。报文体共 **55** 字节：

```json
{"username":"alice","client_ver":"1.0","color":"black"}
```

整帧（8 + 55 = **63** 字节）：

```
43 48 02 01 00 00 00 37
└ magic ┘ │  │  └ len=55 ┘
         ver type
```

完整十六进制：

```
43 48 02 01 00 00 00 37
7B 22 75 73 65 72 6E 61 6D 65 22 3A 22 61 6C 69 63 65 22 2C 22 63
6C 69 65 6E 74 5F 76 65 72 22 3A 22 31 2E 30 22 2C 22 63 6F 6C 6F
72 22 3A 22 62 6C 61 63 6B 22 7D
```

最小帧 `PING`（空体）：`43 48 02 30 00 00 00 02 7B 7D`

## 附录 B　扩展规则

1. **加可选字段**：`ver` 不变，接收方忽略不认识的字段，但必填字段仍要校验。
2. **加必填字段或改语义**：`ver` 升到 3，服务端对 `ver=2` 回 `1003`。
3. **加新类型码**：不得复用已废弃的码；新码必须在第 3 章登记后才允许写代码。
4. **不允许**在 `body` 里塞二进制。
